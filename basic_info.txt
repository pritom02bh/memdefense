--------------------------------------------------------------------------------
2. RUNNING THE METERING PROXY
--------------------------------------------------------------------------------

The proxy must be running in its OWN terminal window whenever you make
LLM calls. Everything else happens in a second terminal.

TERMINAL 1 -- start the proxy:

cd ~/Desktop/"Research Files"/memdefense
source .venv/bin/activate
set -a
source .env
set +a
litellm --config proxy/config.yaml --port 4000

Leave it running. Look for:  "Uvicorn running on http://0.0.0.0:4000"

To stop it:  press Ctrl + C in that window.

What the three "set" lines do:
  set -a       -> mark everything defined next for export to child processes
  source .env  -> read the API key into the shell
  set +a       -> stop auto-exporting
Without these, litellm cannot see OPENAI_API_KEY and calls will fail.

  -H "Content-Type: application/json" \

PASS CRITERIA:
  - exactly 3 lines
  - no line has "status": "logger_error"
  - lines 1 and 2 show "purpose": "base"
  - line 3 shows "purpose": "defense"
  - tokens_in / tokens_out match the API's own usage numbers

To see the full API response (including usage) instead of discarding it,
drop the  > /dev/null  and add:   | python3 -m json.tool

4. READING THE LOGS
--------------------------------------------------------------------------------

# raw
cat results/proxy/calls.jsonl

# pretty-print each line
cat results/proxy/calls.jsonl | while read l; do echo "$l" | python3 -m json.tool; done

# count calls
wc -l < results/proxy/calls.jsonl

# total cost so far
python3 -c "
import json
rows=[json.loads(l) for l in open('results/proxy/calls.jsonl')]
print('calls:', len(rows))
print('total tokens:', sum(r.get('tokens_total',0) for r in rows))
print('total USD: \$%.6f' % sum(r.get('cost_usd',0) for r in rows))
"

# cost split by purpose  (this is the paper's core measurement)
python3 -c "
import json, collections
rows=[json.loads(l) for l in open('results/proxy/calls.jsonl')]
agg=collections.defaultdict(lambda:[0,0,0.0])
for r in rows:
    p=r.get('purpose','?')
    agg[p][0]+=1
    agg[p][1]+=r.get('tokens_total',0)
    agg[p][2]+=r.get('cost_usd',0)
for p,(n,t,c) in sorted(agg.items()):
    print(f'{p:10} calls={n:5} tokens={t:8} usd=\${c:.6f}')
"

# find any logger failures
grep logger_error results/proxy/calls.jsonl

# clear the log
rm -f results/proxy/calls.jsonl

6. TROUBLESHOOTING
--------------------------------------------------------------------------------

"command not found: python"
  macOS has no bare 'python'. Use python3, or activate the venv first.

"command not found: litellm"
  The venv is not activated:  source .venv/bin/activate

Proxy starts then exits with ImportError about the callback
  The callback path in proxy/config.yaml is resolved relative to the folder
  CONTAINING config.yaml. Since config.yaml lives in proxy/, the value must be
  "logger.metering_logger"  --  NOT "proxy.logger.metering_logger".

calls.jsonl is missing or empty after making calls
  1. Did you restart the proxy after editing logger.py? Python loads code at
     startup; edits on disk do not affect a running process.
  2. Check for a swallowed exception:  grep logger_error results/proxy/calls.jsonl
  3. Test the write path directly:
       python3 -c "import sys; sys.path.insert(0,'proxy'); import logger; \
       print(logger.LOG_FILE); logger._write_line({'t':1}); print('ok')"

All lines show "purpose": "base" even when a different tag was sent
  Headers live at kwargs["litellm_params"]["proxy_server_request"]["headers"].
  Already fixed in logger.py -- if it reappears, that path changed.

ImportError: get_flat_dependant
  fastapi is >= 0.120.  Fix:  pip install "fastapi>=0.115,<0.120"

ResolutionImpossible / pytz conflict
  Letta must NOT be pip-installed here. It runs in Docker (Component 5).

Port 4000 already in use
  lsof -ti:4000 | xargs kill -9

API key not picked up
  Re-run:  set -a; source .env; set +a
  Verify:  echo $OPENAI_API_KEY | cut -c1-7
